# Melodust Sync Server

Акаунти + синхронізація в реальному часі (WebSocket, із запасним HTTP-polling) для Melodust Web.
Синхронізуються: обране, плейлисти, історія, радіостанції, лічильники відтворень, тема/мова/еквалайзер/8D та інші налаштування.
Аудіофайли, черга й гучність лишаються на пристрої.

## Запуск

```bash
cd server
npm install
npm start            # http://localhost:3000  — сервер сам віддає і сайт, і API
npm test             # інтеграційний тест (потрібен Node 22+)
```

Потрібен Node.js 18+. Дані зберігаються у `server/data/db.json` (робіть його резервну копію).

## Два варіанти розгортання

**1. Один сервер на все (простіше).** Запусти `npm start` на хості з Node.js і направ домен на нього
(напр. `melodust.xgroupsoftware.xyz`). Нічого міняти не треба — `js/config.js` лишається `api: ''`.

**2. Сайт окремо (статика на CityHost), сервер окремо.** Підніми сервер на будь-якому Node-хості/VPS
з HTTPS, наприклад `https://sync.xgroupsoftware.xyz`, і впиши в `js/config.js`:

```js
window.MW_SYNC = { api: 'https://sync.xgroupsoftware.xyz', disabled: false };
```

На сервері за потреби обмеж CORS: `ALLOWED_ORIGINS=https://melodust.xgroupsoftware.xyz`.

## Reverse proxy (nginx) — важливо для WebSocket

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_read_timeout 120s;
}
```
і запускай із `TRUST_PROXY=1`, щоб ліміти спроб входу рахувались по реальній IP.
Якщо проксі не пропускає WebSocket, застосунок сам перейде на HTTP-опитування (оновлення раз на ~12 с).

## Змінні середовища

| Змінна | За замовчуванням | Що робить |
|---|---|---|
| `PORT` / `HOST` | `3000` / `0.0.0.0` | Адреса прослуховування |
| `DATA_DIR` | `./data` | Де лежить `db.json` |
| `ALLOWED_ORIGINS` | `*` | CORS, список через кому |
| `ALLOW_REGISTER` | `1` | `0` — закрити реєстрацію нових акаунтів |
| `TRUST_PROXY` | `0` | `1` — брати IP з `X-Forwarded-For` |
| `SERVE_STATIC` | `1` | `0` — не віддавати сайт, лише API |
| `RESEND_API_KEY` | — | Ключ Resend (`re_...`). Без нього відновлення пароля вимкнене |
| `MAIL_FROM` | — | Відправник, напр. `Melodust <noreply@xgroupsoftware.xyz>` (домен підтверджений у Resend) |
| `SITE_URL` | перший не-`*` з `ALLOWED_ORIGINS` | Адреса сайту для посилання в листі, напр. `https://web.melodust.xgroupsoftware.xyz` |
| `REGISTER_LIMIT` | `5` | Спроб реєстрації з однієї IP на годину |

## Як це працює / обмеження

- Конфлікти вирішує «останній запис виграє» окремо для кожного запису (трек в обраному, плейлист, налаштування).
  Годинники пристроїв вирівнюються по серверу. Різні поля не затирають одне одного.
- Плейлисти й обране прив'язані до id треку (`папка/шлях|розмір`). Щоб вони збігалися на ПК і телефоні,
  папка з музикою має називатись однаково і мати ті самі файли на тих самих відносних шляхах.
- Лічильники відтворень зливаються як максимум по кожному треку.
- Перший вхід: локальні обране/плейлисти **об'єднуються** з акаунтом; налаштування беруться з акаунта,
  а якщо акаунт новий — завантажуються з пристрою.
- Паролі: scrypt із сіллю. Сесії — випадкові токени (зберігається лише SHA-256), термін 90 днів, до 10 пристроїв.
  Є ліміти спроб входу/реєстрації.

## Відновлення пароля (Resend)

1. У [Resend](https://resend.com) додай домен `xgroupsoftware.xyz` (Domains → Add Domain) і внеси SPF/DKIM-записи в DNS. Дочекайся статусу *Verified*.
2. Створи API-ключ (API Keys → Create, права *Sending access*).
3. На сервері задай змінні `RESEND_API_KEY`, `MAIL_FROM`, `SITE_URL` (див. `.env.example`). У логах побачиш `mail: on`.
4. Користувач вказує email при реєстрації або пізніше в Налаштуваннях → Акаунт → Email (для зміни потрібен поточний пароль).
5. «Забув пароль?» → лист із посиланням `SITE_URL/?reset=ТОКЕН`. Посилання діє 30 хв і лише один раз; після зміни пароля всі пристрої виходять з акаунта.

Сервер завжди відповідає однаково, чи існує такий email (щоб не можна було перебирати акаунти). Токени в базі лежать лише як SHA-256.
Ключ Resend ніколи не кладіть у `js/config.js` чи в git — тільки у змінні середовища на сервері.
